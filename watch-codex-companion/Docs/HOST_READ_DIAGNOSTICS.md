# 前台会话读取失败：诊断与本地修复

基线为 `b18b88d2dddce9104f4becd66c775f952388fdf5`。这一基线已通过 [云端验证](https://github.com/10yihang/watch-codex-remote/actions/runs/42668949970)：72 个 Swift 测试、两个无签名模拟器构建及非默认 Bundle ID 产物校验。本文后续修改已获准推送和运行云端构建；批准启动不等于已经通过，最新结果以本轮提交对应的 Actions 为准，不能沿用基线测试结果。

## 已确认的事实与未确认的原因

反馈截图同时显示一台在线主机，以及“请保持 iPhone App 在前台并解锁后操作”。该提示来自 `RemoteConnectionError.foreground`，不是服务端返回的锁屏结论。原实现仅检查 `UIApplication.applicationState == .active`，没有区分短暂 `.inactive` 和真正后台，也没有实际检查受保护数据的可用性。

用户明确表示 iPhone 已在前台并解锁。系统身份验证等界面可能使应用暂时 inactive；原来的同步 Secure Enclave 签名又可能占用 MainActor。两者是可解释症状的代码问题，但截图没有指出具体失败检查点，所以不能认定这一次一定由 Face ID 引起，也不能声称已完成真机复现。

## 修改内容

- 分开处理 active、inactive、background 和受保护数据不可用。短暂 inactive 最多等待五秒；只有 active 且受保护数据可用才继续。真正后台仍立即停止，明确取消仍生效，不保活或自动重连。
- Secure Enclave 用户验证签名移到独立任务，避免在 MainActor 同步等待系统提示。签名前后检查活动状态、取消和挑战有效期。同步系统签名提示本身不保证可被 Task.cancel 立即打断，但取消后不能继续使用其结果。
- 每次活动状态等待后重新验证命令期限，过期指令不发送；未知结果仍记录并锁定，不自动重放。
- 记录安全的当前步骤：主机验证、控制器挑战、系统密钥验证、会话凭据、通道初始化、真实会话列表。失败时显示步骤与错误类别，不输出令牌、账号标识、签名材料、原始服务端响应或任意 URL 错误文本。
- 读取请求保留超时、取消、断网、分块不支持、超出 150 KiB、格式/顺序不符等类别。变更请求遇到不确定结果仍保守处理。
- 根据已检查的参考实现，主机缺少 `busy`/`online` 不再直接拒绝整页；缺失 online 默认不可连接，主机 ID 仍严格校验。控制器期限兼容整秒时间戳和原 ISO 字符串，拒绝分数、布尔、越界或无效值。

最后两项是独立兼容性和诊断问题，不能拿它们作为截图报错的已证实原因。分块响应合并和超大历史支持未在本次扩大。

## 验证与后续验收

本地通过 29 项结构检查（嵌套 OAuth/Bundle 及 11 项 UI 检查）、20 项 Node 离线协议测试及 Python/shell 语法检查。Swift 测试方法共 80 个，新增活动状态决策、读取错误分类、可选主机状态和期限格式用例；初始 Linux 环境没有 Swift/Xcode，随后在上述获批云端运行中执行并通过。

需要在获得批准的 Apple 构建与真机上分别验证：

1. 选择在线主机并确认连接，观察具体停留步骤及错误类别，不把每种失败都归因于解锁。
2. 系统身份验证成功后应用短暂 inactive 再恢复，不应马上错误拒绝；身份验证取消、超时或真正切后台则应终止。
3. 等待期间取消后立即重试，旧操作不能关闭或推进新操作；离开前台不应发送证明或真实命令。
4. 在命令期限附近出现短暂系统界面，过期命令不能发送；断线和未知结果不能自动重发。
5. 超时、网络失败及不支持的响应形状应显示各自类别。不要为了诊断发送真实账号令牌或原始认证日志。

“刷新会话”只刷新已连接通道，不会首次选择主机。首次连接需要选择在线主机并明确确认；最终候选已合并独立的原生材质界面补丁，两个 Live View 的刷新名称和禁用条件也已修正；详情见 [UI_REDESIGN.md](UI_REDESIGN.md)。
